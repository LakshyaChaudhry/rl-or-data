# Phase 3 results — GRPO arms and controls (tasks/04), SPEC v1.8

Small provenance files copied from the artifact store on 2026-09-19 (close-out): `metrics.json`,
`config.yaml`, `config_hash.txt`, `meta.json`, `NOTES.md`, `sanity.json`, `summary.json`, `budgets.json`,
`curves.json`, `grpo_config.json`, `tokenizer_hash.json`, `vllm_policy_sync.json`, `train_log.jsonl`. The
layout mirrors the store: `grpo/<run>/...` here is `$RLORDATA_ARTIFACTS/runs/grpo/<run>/...` on the Lambda
persistent filesystem `rl-or-data`. No file here exceeds 1 MB.

Per-run numbers with n, seeds, bootstrap 95 % CIs, truncation rates and config hashes are in
`reports/tasks04_grpo_acceptance.md` (generated by `scripts/grpo_report.py`). No arm-vs-arm claim is made
here; that is tasks/05.

## What is here

11 runs: `grpo_{mixed,curated,easy}_s{1,2,3}`, `grpo_random_reward_s1` (C1), `grpo_format_only_s1` (C2).
Each has:

- run provenance, `train_log.jsonl` (per-step reward mean/std, frac_reward_zero_std, length, clip ratio,
  grad norm, per-tier reward), `curves.json` (val at steps 100/200/300), `budgets.json`;
- `eval_checkpoints/step_{100,200,300}/val_mixed_100` — val greedy at every checkpoint;
- `eval/val` and `eval/final` — from the step-300 adapter, evaluated once: val_mixed_100, test_300,
  ood_hard_200, gsm8k_500 (greedy and mean@8) and test_300 first-100 pass@k (n = 64).

## Not here

- `reward_records.jsonl` (19,200 records per run, ~5 MB each), `samples.jsonl`, adapters
  (final/100/200/300) and the 12 trainer checkpoints per run: in the store only (276 GB under `runs/grpo`).
  Adapters go to Hugging Face in tasks/07.
- `runs/grpo/_failed/` (the 2026-09-14 bf16-merge collapse of mixed_s1) and the `*.stale-*` logs of the
  curated_s1 attempt that OOMed at step 5: store only. Not results.
- Base-model gsm8k_500 mean@8: never evaluated (the acceptance report labels the row as missing).

## Flags (SPEC §7) — truncation > 5 % on val_mixed_100 or test_300: not headline numbers as they stand

| run | units over 5 % |
|---|---|
| grpo_mixed_s1 | test_300 greedy 6.7 %, mean@8 5.3 % |
| grpo_mixed_s2 | test_300 greedy 10.3 %, mean@8 8.2 %, pass@k 7.3 %; val greedy 9.0 %, mean@8 5.1 % |
| grpo_mixed_s3 | test_300 greedy 9.0 %, mean@8 6.8 %, pass@k 5.2 %; val greedy 8.0 %, mean@8 5.5 % |
| grpo_curated_s1 | test_300 greedy 5.3 % |
| grpo_curated_s2 | test_300 greedy 9.3 %, mean@8 7.1 %, pass@k 6.0 % |
| grpo_curated_s3 | test_300 greedy 8.0 %, mean@8 6.0 % |

The easy arm and both controls stay under 5 % on val and test. ood_hard_200 greedy truncation ranges
7.5–54.5 % across the 11 runs: reported, not flagged, per §7 — but the write-up must state how much of the
ood result is "ran out of tokens". No RFT final unit exceeds 5 % on val or test, so truncation differs
systematically between the RFT and GRPO arms; tasks/05 has to handle that before any H3 comparison.
